# 🏪 إدارة المحل (Shop Manager)

تطبيق أندرويد موحّد يجمع بين مشروعين:
- 📒 **دفتر الديون** (`www/debt`) — إدارة ديون الزبائن.
- 📦 **مدير المواد والأسعار** (`www/materials`) — إدارة المخزون والأسعار.

الواجهتان تعملان كل واحدة بشكل مستقل (بإعدادات Firebase الخاصة بها) داخل غلاف واحد (`www/index.html`)
فيه شريط تنقّل سفلي بأيقونتين للتبديل بين القسمين، بدل ما تتعارض أكواد المشروعين ببعضها.

## كيف بيصير التطبيق جافا (Android APK)؟

المشروع مبني بـ **Apache Cordova**، وهو يولّد مشروع أندرويد أصلي بلغة **Java** (`MainActivity.java` وملفات Gradle)
يشغّل واجهة الموقع (HTML/CSS/JS) داخل WebView. هذا هو الأسلوب القياسي لتحويل تطبيق ويب إلى APK حقيقي بدون
إعادة كتابة كل المنطق بلغة Java من الصفر.

## الإصدار التلقائي عند الرفع لجيتهاب

كل ما تعمل `git push` على فرع `main`، ملف `.github/workflows/release.yml` رح:
1. يثبّت Node + JDK 17 + Android SDK.
2. يضيف منصة أندرويد عبر Cordova.
3. يبني ملف APK (نسخة debug موقّعة تلقائيًا بمفتاح Cordova الافتراضي، تُثبَّت مباشرة على أي جهاز
   بعد تفعيل "السماح بالتثبيت من مصادر غير معروفة").
4. ينشر **Release** جديد على GitHub ويرفق فيه ملف الـ APK تلقائيًا — بدون أي خطوة يدوية منك.

> ملاحظة: هذا APK غير موقّع لمتجر Google Play (توقيع debug). إذا حبيت تنشره على Play Store لاحقًا،
> بدك تولّد keystore وتضيفه كـ GitHub Secret وتعدّل خطوة البناء لتصير `cordova build android --release`
> مع توقيع رسمي — قلي إذا بدك أساعدك بهاي الخطوة لاحقًا.

## خطوات الرفع

```bash
# 1) أنشئ مستودع جديد فاضي على GitHub (بدون README) بالاسم يلي بدك ياه
# 2) بمجلد المشروع:
git init
git add .
git commit -m "Initial commit: شركة إدارة المحل"
git branch -M main
git remote add origin https://github.com/USERNAME/REPO_NAME.git
git push -u origin main
```

بعد الرفع، افتح تبويب **Actions** بالمستودع وتابع البناء، وبعد ما يخلص رح تلاقي الـ APK
تحت تبويب **Releases**.

## هيكل المشروع

```
shop-manager/
├── config.xml              # إعدادات Cordova (اسم التطبيق، الأيقونات، صلاحيات الأندرويد)
├── package.json             # يحدد إصدار Cordova المستخدم بالبناء
├── .github/workflows/release.yml
└── www/
    ├── index.html           # الغلاف الرئيسي (شريط تنقّل بين القسمين)
    ├── css/shell.css
    ├── js/shell.js
    ├── manifest.json
    ├── icons/               # أيقونة التطبيق الموحّدة (متجر) بكل المقاسات
    ├── debt/                # مشروع دفتر الديون الأصلي كاملًا
    └── materials/           # مشروع مدير المواد الأصلي كاملًا
```

## المشاكل اللي انصلحت أثناء الدمج

- كل مشروع كان عندو `firebase-config.js` بمشروع Firebase مختلف تمامًا (`slx23m` و `abo-slman`)
  — تُركا منفصلين تمامًا (كل واحد بقاعدة بياناته) لأن دمجهما بقاعدة وحدة كان يعني إعادة كتابة منطق
  التطبيقين بالكامل؛ الفصل بإطارين (iframes) منفصلين يمنع أي تعارض أسماء أو متغيرات عامة (`window.*`) بينهم.
- تسجيل الـ Service Worker بمشروع المواد كان يستعمل مسار مطلق `/sw.js` يكسر لما ينضم داخل مجلد فرعي
  — تم تصحيحه لمسار نسبي `sw.js`.
- ملف `manifest.json` بمشروع المواد كان فيه `start_url` مطلق (`/material-manager/`) مبني لنشر GitHub Pages
  قديم — تم تصحيحه.
- تمت إزالة سكربت GitHub Pages القديم (`material-manager/github/workflows`) لأنه كان مجرد ملفات ساكنة
  داخل مجلد الموقع ومش ضمن `.github/` الفعلي، واستُبدل بخط أنابيب أندرويد الموحّد.
- تمت إضافة أيقونة تطبيق جديدة (متجر بنفسجي) مناسبة لتطبيق إدارة محل، بدل أيقونة "نبتة" العشوائية
  يلي كانت بمشروع المواد، بكل المقاسات المطلوبة لأندرويد (72 حتى 512).

## أشياء ممكن تحبّ تتحقق منها بنفسك

- كل قسم إلو زر رجوع/تحديث خاص فيه؛ زر الرجوع الفيزيائي بالأندرويد رجّعناه يفتح تبويب "الديون" أول ما تضغطه
  من أي قسم تاني، وبعدين يطلب تأكيد ثاني قبل ما يقفل التطبيق.
- إذا في ميزات كانت تعتمد على service worker/إشعارات push بمشروع المواد، هاي بتشتغل بس لما يكون
  فيه اتصال إنترنت حقيقي (نفس سلوكها الأصلي بالمتصفح).
