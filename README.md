# 🏪 إدارة المحل (Shop Manager) — نسخة أندرويد أصلية احترافية

تطبيق أندرويد **حقيقي** (Kotlin + Jetpack Compose) — مو متصفح ومو WebView — بواجهة وثيم
احترافيين، وطبقة بيانات Firebase مبنية من الصفر لتصلح كل الأعطال المكتشفة بالنسختين
الأصليتين.

## 1) فحص شامل لكل الملفات — كل الأعطال المكتشفة

بعد فحص كل ملف JS بالمشروعين (مو بس اللي كان واضح سابقًا)، هاي كل الأعطال المؤكدة:

### مدير المواد (material-manager) — كان معطّل بالكامل مع Firebase
الأسماء `isFirebaseReady()` و`getDB()` و`COLLECTION`/`PRICES_COLLECTION` **غير معرّفة
بأي مكان بالمشروع كله**، وهاي مستخدمة بـ:
- `materials.js` — كل عمليات المواد (إضافة/تعديل/حذف/تحميل)
- `prices.js` — كل عمليات الأسعار
- `events.js` — زر المزامنة اليدوي وبحث الأسعار
- `dragdrop.js` — **سحب وإفلات المواد بين الأقسام كمان معطّل لنفس السبب**، اكتشاف جديد
  بالفحص الموسّع هالمرة

يعني عمليًا التطبيق القديم ما كان يتكلم مع Firebase إطلاقًا من أي مكان — كان يشتغل حصرًا
محليًا (`localStorage`) من أول تشغيل.

### دفتر الديون (debt-app)
- تعارض `enableIndexedDbPersistence()` مع `persistentLocalCache` (مشروح بالتفصيل بالنسخة
  السابقة) — تم إصلاحه بإعداد الكاش مرة وحدة فقط بـ `FirebaseModule.kt`.
- إحصائيات الهيدر ما كانت تتحدث لحظيًا إلا بتغيّر قائمة الزبائن — تم إصلاحه بمستمع منفصل
  على كل الديون.
- ملفات `auth.js` و`security.js` و`encryption.js` و`backup.js` موجودة بالمستودع لكنها
  **غير محمّلة إطلاقًا** بـ `index.html` (كود ميت) — يعني التطبيق القديم بلا أي حماية
  دخول حقيقية رغم وجود كود جاهز إلها. استبدلناها بقفل PIN محلي شغّال فعليًا (تفاصيل تحت).

### عطل بالكود الأصلي لهاي النسخة (Kotlin) تم اكتشافه وإصلاحه بهاي الجولة
كان `DebtsViewModel` و`MaterialsViewModel` يستخدموا Constructor بقيمة افتراضية
(`DebtsRepository = DebtsRepository()`) — Kotlin ما بيولّد Constructor بدون معاملات
حقيقي على مستوى الـ JVM لهيك حالة، فمصنع `viewModel()` الافتراضي بأندرويد كان رح يطيح
بخطأ `NoSuchMethodException` وقت التشغيل. تم تبسيطها لتهيئة مباشرة بدل معامل constructor.

## 2) الثيم والستايل — بُني من الصفر باحترافية

- **نظام ألوان كامل** (`ui/theme/Color.kt`): بالِت indigo/violet متناسق مع أيقونة
  التطبيق، بنسختين فاتحة وداكنة، وألوان دلالية (نجاح/تحذير/خطر) موحّدة بكل الشاشات.
- **نظام خطوط متدرج** (`ui/theme/Typography.kt`): 9 مستويات (Headline → Label) بدل
  الاعتماد على القيم الافتراضية.
- **أشكال موحّدة** (Rounded corners متدرجة) لكل البطاقات والحقول والأزرار.
- **ثيم قابل للتبديل**: فاتح / داكن / حسب النظام، محفوظ محليًا ويطبّق فورًا من الإعدادات.

## 3) ميزات جديدة مفيدة للمحل

| الميزة | الوصف |
|---|---|
| 🏠 شاشة رئيسية (لوحة تحكم) | نظرة عامة فورية: إجمالي الديون، عدد العملاء، عدد المواد، أكبر 5 ديون، وتنبيهات نفاد المخزون. |
| ⚠️ تنبيه نفاد المخزون | حدّد "حد تنبيه" لأي مادة؛ لما الكمية توصله، بتنعلّم بقائمة المواد وبشريط تحذير وباللوحة الرئيسية. |
| 🔍 بحث بالمواد | كان البحث موجود بالديون بس ناقص بالمواد — أضفناه. |
| 📤 مشاركة/تصدير | زر مشاركة بأعلى شاشتي الديون والمواد يصدّر كشف نصي جاهز (واتساب/بريد) بكل الأرصدة أو المواد والأسعار. |
| 🔒 قفل PIN محلي فعلي | بديل شغّال لملفات auth.js/security.js الميتة بالنسخة القديمة: رمز 4-6 أرقام مشفّر (SHA-256) على الجهاز. |
| 🎨 إعدادات مركزية | شاشة إعدادات وحدة: تبديل الثيم، تفعيل/إلغاء القفل، حد التنبيه الافتراضي. |

## البنية المعمارية (بعد إعادة التنظيم)

```
app/src/main/java/com/shopmanager/app/
├── MainActivity.kt              # نقطة الدخول + بوابة القفل + شريط تنقّل بـ 3 تبويبات
├── data/
│   ├── FirebaseModule.kt        # مشروعا Firebase الأصليان، بإعداد كاش صحيح بدون تعارض
│   ├── settings/                 # SettingsRepository — الثيم، القفل، حد التنبيه
│   ├── debts/                    # نماذج ومستودع الديون
│   └── materials/                 # نماذج ومستودع المواد والأسعار
└── ui/
    ├── dashboard/                 # الشاشة الرئيسية / لوحة التحكم (جديدة)
    ├── debts/                     # شاشات الديون
    ├── materials/                  # شاشات المواد والأسعار
    ├── settings/                   # شاشة الإعدادات (جديدة)
    ├── lock/                       # شاشة قفل PIN (جديدة)
    └── theme/                      # الألوان، الخطوط، الأشكال (أُعيد بناؤها بالكامل)
```

## ⚠️ لسا لازم تتحقق منه بنفسك

نفس ملاحظة الجولة السابقة: افتح Google Cloud Console → APIs & Services → Credentials
لكل من مشروعي `slx23m` و`abo-slman` وتأكد إن الـ API keys مو مقيّدة بـ HTTP referrer
لأنها هلق هتُستدعى من تطبيق أندرويد أصلي.

## شو ما زال غير منقول (بعد)

- الذكاء الاصطناعي لتحليل المخزون، القوائم الجاهزة (Presets)، وترتيب المواد بالسحب
  والإفلات بين الأقسام من مدير المواد القديم.
- توحيد قاعدتي بيانات Firebase بقاعدة وحدة (لسا منفصلتين تقنيًا، بواجهة موحدة بالكامل).

قلي أي منها بدك وبضيفه.
